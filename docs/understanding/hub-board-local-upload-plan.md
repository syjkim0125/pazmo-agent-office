# 설계: 칸반 보드 Hub와 로컬 올리기 (D42)

상태: G3 승인 2026-11-11(사용자 "승인, 시작해"). Story `docs/understanding/pazmo-agent-office-contract.md`의 D42·V20(G1 2026-11-11). 설명 페이지 https://claude.ai/artifact/GJBHwuZJSNs9xqUJDPQKAR

## 무엇이 바뀌나 (사람에게 보이는 것)

PL이 자기 Mac의 claude와 대화해 Story와 Task를 만든 뒤 "허브에 올려줘"라고 하면, claude가 명령 하나(`pazmo-office team upload`)를 부릅니다. 명령은 승인 기록과 Task 그래프를 확인하고, 통과하면 Hub에 올리고, 레포마다 Story base를 만들고, Story를 엽니다. 몇 초 뒤 팀원 Mac의 Office가 할 일 칸의 카드를 가져가고, 모두가 보는 Hub 첫 화면(칸반)에서 카드가 백로그 → 할 일 → 진행 중 → 리뷰 → 완료로 저절로 움직입니다. 카드마다 맡은 사람, 그 사람 Mac 상태, 그 칸에 머문 시간이 보입니다.

예: PL 지수가 claude에 "결제 Story 허브에 올려줘"라고 합니다. 명령이 "MUST 3이 어느 Task에도 없습니다"로 멈추면 Hub에는 아무것도 생기지 않습니다. claude가 Task를 고쳐 다시 부르면 Story #8이 열리고, A의 카드가 "진행 중 · A · Mac 일하는 중 · 2분째"로 보입니다.

## 정한 것과 고르지 않은 것

| # | 정한 것 | 고르지 않은 대안과 이유 |
|---|---|---|
| K1 | **올리기는 명령이 직접 한다.** PL Mac에서 도는 명령이 Hub의 새 연결 경로 `POST /api/link/story/upload`(프로토콜 3)로 Story와 Task를 올리고, Story base를 만들고, 기존 `open`으로 연다. AI는 쓰지 않는다. 묶음 3의 Story base 만들기·열기 코드(`basesAndOpen`)를 `createPlanner` 밖으로 꺼내 기획 Office와 명령이 함께 쓴다. | Hub 기획 기록(`PlanBoard`)에 넣고 PL의 Office가 가져가게 하기: Office가 다른 Task를 하는 동안 몇 시간 기다릴 수 있고(한 번에 하나), 기획 확인 코드는 Office가 쓴 초안 모양만 받아서 사람이 쓴 kit Story는 크게 고쳐야 받는다. |
| K2 | **로컬 승인은 두 곳에서 확인한다.** 명령: Story의 G1 줄이 가리키는 kit G1 기록이 그 Story 글의 kit 해시(`kitStoryHash`, kit `storyContract`와 같은 계산)에 묶였는지. Hub: 요청한 연결이 그 PL의 **지금 Mac**이 만든 연결인지(연결 문자열로 만든 Mac 없는 연결은 거절), 그 PL이 프로젝트의 모든 레포 담당자인지. Hub는 "로컬 승인 · Mac 이름 · Story 해시 · 시각"을 기록하고 Story 화면에 보인다. | 올린 뒤 Hub에서 [열기] 한 번 누르기: G1 때 기본값으로 보였고 사용자가 고르지 않았다. 사람이 누른 것은 Hub가 확인하지 못한다는 한계는 설계 문서에 남긴다. |
| K3 | **검사는 명령이 먼저, Hub가 다시.** 명령: Story 모양(kit 틀, M마다 Verify), 그래프(순환·프로젝트 밖 레포·같은 레포 파일 겹침·한도, Hub와 같은 `validateGraph`), MUST·Verify 덮임(D35 P5 `coverageOf`, Task마다 `covers`), Task 검사마다 V 번호, 프로젝트의 레포·기준 브랜치가 그래프와 같은지. 하나라도 틀리면 Hub를 부르지 않고 쉬운 이유를 낸다. Hub는 지금 `publishStory`의 그래프 검사를 그대로 다시 한다. | Hub에서만 검사: 이유가 Hub 코드로 돌아와 claude가 고치기 어렵다. |
| K4 | **멱등과 이어 하기.** Hub 올리기 키는 `upload:<Story 해시>`(지금 `publishStory`의 PL·키 멱등). Story base 커밋은 Hub에 레포마다 한 번만 적고 다른 커밋이면 거절한다(묶음 3의 `BASES_CHANGED`와 같음). 같은 명령을 다시 부르면 남은 단계부터 한다(이미 올림 → base → 열기). 열리기 전의 올린 Story는 PL이 웹 Story 화면에서 [취소]할 수 있다. | 매번 새로 올리기: 실패 뒤 다시 부르면 Story가 둘 생긴다. |
| K5 | **보드.** `/`가 보드다. 프로젝트마다 Story 한 줄(레인)에 Story 카드와 Task 카드 다섯 칸. 칸 정하기: 앞 Task 기다림 → 백로그, 할 일 → 할 일, 맡음(단계 없음·구현) → 진행 중, 맡음(리뷰·검증·머지) → 리뷰, 머지됨·검증 통과 → 완료. 멈춤(Mac 소식 없음)과 실패는 마지막 단계의 칸에 "멈춤"과 쉬운 이유. 취소는 숨김(보기 켜면 보임). 완료 칸은 최근 다섯 장과 "N개 더". 웹 기획 중인 것과 열리기 전 Story는 "기획 중" 레인. "칸에 머문 시간"은 Task 표에 새 칸 `column_at`(`ALTER TABLE … ADD COLUMN`, 옛 행은 맡은 때 또는 만든 때)을 두고 칸이 바뀔 때만 적는다. 화면 하나에 쿼리 수가 프로젝트·Story 수와 상관없이 일정하도록 보드용 조회 셋(Story들, Task들, 사람별 Mac 상태)을 새로 둔다. | 사람이 카드를 옮기기: 금방 실제와 달라진다. Task 이벤트 표에서 시각 찾기: 단계가 바뀔 때 이벤트가 없다. |
| K6 | **저절로 업데이트.** 새 `/live.js`(`/copy.js`처럼 서버가 주는 파일)를 GET 화면(보드, 내 할 일, 팀, Story, Task, 기획, 내 Mac)에만 넣는다. 10초마다, 탭이 보이고 입력 칸에 바뀐 값이나 포커스가 없을 때만 같은 주소를 `If-None-Match`로 다시 읽고, Hub가 304가 아니라 새 HTML을 주면 `<main>`과 제목만 바꾼다. 401이면 멈춘다. CSP에는 `connect-src 'self'` 하나만 더한다. 스크립트가 없으면 새로 고침 링크가 그대로 보인다. | 10초마다 `location.reload()`: 화면이 깜박이고 스크롤이 튄다. SSE: 연결을 오래 잡고, 라우터 뒤 시간 제한을 따로 맞춰야 한다. |
| K7 | **들어오기와 메뉴.** 로그인 없이 허용된 화면(보드, Story, Task, 기획, 팀, 내 할 일, 내 Mac)을 열면 그 경로를 72시간 쿠키로 기억하고, 초대 링크로 들어오면 그 경로로, 없으면 보드로 간다(`/`로 시작하고 `//`·`\`가 없고 허용 목록에 맞을 때만). 메뉴는 보드·팀 둘이고 오른쪽에 자동으로 일하기 스위치와 내 Mac 상태. 지금의 내 할 일은 `/me`로 옮기고, 누구나 보는 새 `/team`(사람마다 Mac 상태, 지금 하는 Task, 자동으로 일하기, 그리고 레포·내 Mac·팀원·초대(관리자)·인증서 링크)을 둔다. `/start`·`/connect`의 낡은 안내는 지금 쓰는 `hub-link --connect` 방법으로 고친다. 보드 없는 Hub는 지금 그대로다. | 401이 난 마지막 주소 기억: 브라우저의 `/favicon.ico` 같은 요청이 덮어쓴다. |
| K8 | **claude용 안내.** `pazmo-office team upload --guide`가 파일 모양과 쓰는 법을 출력한다. 같은 글을 `skills/pazmo-hub-upload/SKILL.md`로 저장소에 두고, Mac 연결 명령이 `~/.claude/skills/pazmo-hub-upload/SKILL.md`로 복사한다(우리가 쓴 파일이면 덮어쓰고, 사용자가 고친 파일이면 두고 알린다). | 사람이 매번 형식을 알려 주기: claude가 그래프 형식을 추측해 틀린다. |
| K9 | **사람 말과 상태 색.** Story 화면의 Story base 표·PR, Task 화면의 PR·머지 커밋·파일 경로·검사 명령은 "개발 정보" 접기로, `ASSUMED:` 줄은 "AI가 정한 것"으로, G1·G3 기록은 "초안 승인(G1)"·"설계 승인(G3)"으로. 상태 표시는 글자와 네 색(답해 주세요·진행 중·멈춤·끝남). 글자 크기 13·15·19·26px. | — |

## 꼭 지킬 것 (깨지면 실패)

- 명령이나 Hub의 검사 하나라도 실패하면 Hub에 아무것도 생기지 않는다(올린 Story도, base도).
- 같은 Story 글(해시)로 Story가 둘 생기지 않는다.
- 원격 쓰기는 `feature/story-<N>/base` 만들기 하나뿐이고, 강제 push·다른 ref push·지우기는 없다. 같은 이름에 다른 커밋이 있으면 멈춘다.
- 다른 사람의 연결, 연결 문자열로 만든(Mac 없는) 연결, 해제된 Mac으로는 올리지 못한다.
- 저절로 업데이트는 입력 중인 글이나 포커스를 지우지 않고, POST 결과 화면·일회용 값 화면을 다시 읽지 않는다.
- 웹 기획(묶음 3), Task 버튼, 웹 승인의 해시·revision 확인, 권한, 연결 프로토콜의 기존 경로는 그대로다. 새 경로는 더하기만 한다.

## 실패와 복구

- 명령 도중 실패(네트워크, push 거절, 열기 실패): Hub에는 "기획 중(열리기 전)" Story로 남고, 같은 명령을 다시 부르면 남은 단계부터 한다. 그만두려면 PL이 웹에서 [취소].
- 되돌리기: 코드 되돌리면 지금 화면으로 돌아간다. 새 표·새 칸은 더하기만 해서 그대로 둬도 옛 코드가 읽지 않는다. 올린 Story는 보통 Story와 같다.

## 증거

- 자동 시험: 칸 정하기 표 전부, 멈춤·취소·완료 다섯 장, Story 카드의 사람, Mac 상태·머문 시간과 칸 바뀔 때만 시각이 바뀜, 내 것만, 보드 쿼리 수 고정, 로그인 전 주소(허용·밖 주소·`//` 거부·72시간), 메뉴·`/me`·`/team`·옛 주소, 저절로 업데이트(304, 바뀐 HTML, 입력 중·포커스·숨은 탭이면 안 바꿈을 vm으로 실행, GET 화면에만 스크립트, CSP), 이스케이프, 개발 정보 접기, 올리기 거부(G1이 글과 다름·G1 없음·남의 연결·Mac 없는 연결·담당 아님·그래프 오류·덮임 부족·레포나 기준 브랜치 다름)와 성공(올림·base·열기), 다시 불러도 하나, 도중 실패 뒤 이어 하기, 열리기 전 취소, 웹 기획 Story와 올린 Story가 같은 보드에. 실제 TLS Hub와 로컬 bare repo, 가짜 `gh`로 끝에서 끝.
- 실제 확인: 이 Mac 로컬 Hub와 시험 repo 두 개로 PL이 claude 대화에서 올리고 팀원 Office가 끝내는 데까지 한 번.
- 확인하지 못하는 것: 사내 Hub 재배포, 두 사람의 실제 Mac, 실제 claude가 쓴 그래프의 질.

## 나눠 만들기 (행동 기준, 차례대로)

1. **보드 데이터.** Task가 칸을 바꾼 때를 기록하고, 보드를 일정한 쿼리로 읽는다. → 2의 재료.
2. **보드 화면과 메뉴.** `/` 보드, `/me`, `/team`, 메뉴 둘, 자동으로 일하기 스위치가 있던 곳으로 돌아오기. → 사람이 보는 첫 화면.
3. **저절로 업데이트.** `/live.js`, ETag/304, CSP. → 2의 화면이 살아 움직임.
4. **들어오기.** 로그인 전 주소 기억, 초대 뒤 보드, `/start`·`/connect` 문구.
5. **사람 말과 상태 색.** Story·Task·기획 화면의 개발 말 접기.
6. **Hub 올리기 경로.** `upload`, 연결의 Mac 확인, 로컬 승인 기록, base 커밋 기록, 열리기 전 취소. → 7이 부름.
7. **올리기 명령.** `team upload`(검사, 올리기, base, 열기, 이어 하기, `--guide`), `basesAndOpen` 꺼내기. → 6을 씀.
8. **안내와 문서.** SKILL.md와 Mac 연결 때 복사, LOCAL-PREVIEW, 변경 기록, kit 검증 프로필에 V20.
