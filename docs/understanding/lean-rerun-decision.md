## 사용자 요청 (2026-10-27)

eevee-be 실제 확인에서 엔진이 멈춘 작업(`UNKNOWN_RESULT`, 작업 상세의 "멈춤")에는 "작업 취소"만 있어서, 같은 작업을 두 번 취소하고 새로 만들었다([검증 기록](../verification/2026-10-21-lean-office-phase1.md) "실제 확인에서 찾은 것" 3). 멈춘 작업을 작업 상세에서 다시 돌리는 가장 작은 방법을 찾는다.

## 지금 상태 (코드 근거, `1e7883e`)

- **기획 단계 실패:** 엔진이 `planning-retry` 결정("계획 재개")을 연다. 사람이 이유를 적어야 다시 돌고 횟수 제한이 있다(`native-office.ts` pump, `intake.retryPlanning`).
- **구현·검증 단계 멈춤:** 검증 round가 `human_required`(`UNKNOWN_RESULT`, `DEADLINE_EXCEEDED`, `CONTROLLER_RESTARTED`, `DISPATCH_FAILED` 등)가 되면 하위 작업은 `pending`으로 남는다. 엔진은 결정을 열지 않는다.
  - `verification.ts` `begin()`은 "Explicit recovery is required; no automatic retry."로 새 round를 거부한다.
  - `budgets.ts`에는 작업당 구현 3회·예약 60분 한도가 있고, 이런 멈춤의 복구는 "until explicit recovery is built"로 남아 있다.
  - kit 그래프도 사람 필요 상태를 되돌리지 않는다(`kit-planning.ts`).
- **실행 실패·재시작 보류:** 엔진은 메시지만 남긴다. lean은 이 메시지를 읽어 멈춤으로 보인다(`STOP_NOTICES`).
- **Claw Office의 Run:** `/tasks/:id/run`이 `office.assign` → `pump()`만 부른다. 멈춘 단계는 그대로다.
- **lean `office.ts`:** 작업 만들기, 결정 답하기, 취소만 있다.

## 결정

1. **경로.** `POST /api/tasks/:id/rerun`. 몸통은 새 작업과 같은 `{title, body, agentId, risk}`다. 다른 쓰기 경로와 같이 `127.0.0.1`·세션·CSRF를 거친다.
2. **대상.** 지금 멈춤인 요청(lean `stopOf`가 이유를 주는 루트 작업)만 받는다. 아니면 `NOT_STOPPED`(409)다. 진행 중, 결정 대기, 완료, 취소된 작업이 여기에 든다.
3. **순서.**
   - 새 작업을 만든다. 검사(입력, 실행기, 멈추는 중)는 새 작업 만들기와 같다.
   - 새 작업 행과 "다시 실행" 연결 행은 한 트랜잭션에서 저장한다. 같은 작업을 두 번 다시 실행하려 하면 거부한다(`ALREADY_RERUN`, 409). 연결 행의 유일 조건이 마지막 방어선이다. 두 탭에서 동시에 눌러도 새 작업은 하나다.
   - 그 트랜잭션 안에서 멈춤 여부도 다시 본다. 실행기 확인을 기다리는 동안 다른 탭에서 취소됐으면 `NOT_STOPPED`이다(독립 리뷰 지적 반영).
   - 엔진이 새 작업을 받아들인 뒤에만 멈춘 작업을 취소한다(기존 취소와 같은 엔진 경로).
   - 새 작업이 엔진에 들어가기 전에 거부되면 연결도 남지 않고, 멈춘 작업은 그대로다.
4. **연결.**
   - lean 저장 파일에 `task_reruns(task_id, previous_id)` 표를 더한다. 기존 lean 저장 파일에도 시작할 때 만들어진다.
   - 작업 상세는 `rerunOf`(이 작업이 다시 실행한 작업)와 `rerunBy`(이 작업을 다시 실행한 작업)를 `{id, title}`로 준다. 화면은 둘을 링크로 보인다.
   - 두 작업의 진행 기록에도 한 줄씩 남긴다.
5. **취소가 실패하면.** 새 작업은 남긴다(다시 만들면 중복된다). 응답은 `previousCancelled: false`이고, 새 작업 진행 기록에 이유를 남긴다. 화면은 "이전 작업은 직접 취소하세요"를 알린다.
6. **화면.**
   - 멈춘 작업 상세에 [다시 실행]이 [작업 취소] 옆에 보인다.
   - 누르면 새 작업 창과 같은 화면 안 창이 열린다. 제목·내용·위험도가 채워지고, agent는 가정 3대로 골라진다.
   - 창에 "새 작업을 만들고 이 작업을 취소합니다. 취소는 되돌릴 수 없습니다."가 보인다.
   - 성공하면 새 작업 상세로 간다. 멈춤 안내 문구는 다시 실행을 함께 안내한다.
7. **바꾸지 않는 것:** 엔진(`src/core`, `src/runtime/native-office.ts`, `src/runners`), Claw Office, 결정 규칙, 대기열(한 번에 하나), 실행 예산.

## 실패 처리

| 상황 | 동작 |
|---|---|
| 멈춤이 아닌 작업 | 409 `NOT_STOPPED`, 아무것도 저장하지 않음 |
| 이미 다시 실행한 작업(두 번째 요청) | 409 `ALREADY_RERUN`, 새 작업 없음 |
| 실행기 확인을 기다리는 동안 다른 탭에서 취소됨 | 409 `NOT_STOPPED`, 새 작업 없음 |
| 입력 오류·실행기 준비 안 됨·멈추는 중 | 새 작업 만들기와 같은 오류, 멈춘 작업 그대로 |
| 새 작업이 엔진에 들어간 뒤 시작만 실패 | 새 작업은 남고(기존 규칙) 멈춘 작업은 취소 |
| 멈춘 작업 취소 실패 | 새 작업은 남김, `previousCancelled: false`, 새 작업 기록에 이유 |
| 세션·CSRF 없음 | 401 / 403 (기존) |

## 검증 (V17 추가분)

- 자동 시험:
  - 멈춘 요청 다시 실행: 기획 멈춤, 하위 작업 `UNKNOWN_RESULT`
  - 새 작업의 내용·agent·위험도, 대기열
  - 이전 작업 취소, 양쪽 링크와 기록
  - 멈춤 아님 거부, 중복 거부(동시 요청 포함)
  - 새 작업 거부 시 멈춘 작업 유지
  - 취소 실패 시 응답과 기록
  - 서버 경로의 세션·CSRF
  - 화면: 버튼 조건, 기본 대화상자 없음, 문구 ko/en
- 기존 시험은 모두 통과해야 한다.
- 실제 확인(이번 범위 밖, 사용자 Office 재시작이 필요해 요청할 때 한다): eevee-be에서 멈춘 작업 하나를 다시 실행한다.

## 대안과 복구

- **B. 엔진 실행 재개 결정:** Story·계획 승인을 살리지만 엔진 핵심을 바꾼다(검증 기록, 예산, kit 복구, 멈춤 종류별 규칙). 그래서 고위험이고 Claw Office에도 보인다. 멈춤이 계속 자주 나오면 별도 G3로 다룬다.
- **엔진을 다시 깨우는 경로:** Claw의 Run과 같아서 멈춘 단계는 그대로다. 버렸다.
- **복구:** 경로 하나, 버튼 하나, 표 하나를 더하는 변경이라 되돌리기 쉽다. 표는 비어 있어도 무해하다. 단, 사용자가 누른 뒤 멈춘 작업의 취소는 되돌릴 수 없다(확인 문구로 알린다).
