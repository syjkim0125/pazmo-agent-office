## 사용자 요청 (2026-10-20)

사용자는 Claw Empire에서 쓰지 않는 기능을 모두 없애고 싶다고 했다. 필요한 기능은 9가지로 정리했다.

1. 다른 팀원과 협업하는 Tasks 기반 도구
2. 다른 팀원에게 Task를 보내 그 팀원의 agent가 수행
3. 받은 팀원이 수락·취소·거절
4. 자기 AI 구독(CLI) 자동 연동
5. Decisions 보고 결정·답변
6. 기본은 ai-workflow-kit
7. agent 역할은 사람이 지정
8. agent 추가·제거·이름 변경
9. agent 목록

사용자의 말로는 "주로 task 칸반보드랑 decisions만 보게 되는데... 오히려 기능이 많으니까 헷갈려"였고, "claw-empire를 싹 다 없애고 처음부터 새로 만들어도 돼"라고 했다.

## 지금 상태 (조사 근거)

- **Claw Empire 규모:** 서버 약 5.1만 줄, 화면 약 4만 줄, 의존성 540MB다.
- **Office 모드(`PAZMO_MANAGED=1`)에서 막아 둔 기능**(쓰기 시 423): 부서, agent 추가·삭제, 하위 작업, 회의, 공지, 지시, 스킬, GitHub 가져오기, 워크플로 팩, 설정(OAuth·API·게이트웨이), 메신저, 업데이트, 방 꾸미기, 터미널.
- **9가지 중 이미 Pazmo 코드인 것:** 2·3·4·6번과 5번의 내용이다. 5번의 Decisions는 `office.currentDecisions`로 내용이 교체돼 있다.
- **Claw 화면을 쓰는 것:** 1번(칸반)과 9번(목록)이다.
- **없거나 막힌 것:**
  - 7번: 지금은 부서·직급으로 자동 매핑한다(`native-office.ts:160-173`).
  - 8번: agent POST/DELETE가 막혀 있다.
- **새 앱이 와도 그대로 쓰는 것:** `src/core`(약 4.3k줄), `src/runners`, `src/hub`, 허브 연결·보내기·받기, 결정 요약, CLI.
- **다시 짜야 하는 것:**
  - `claw-service.ts`
  - `native-office.ts` 중 Claw에 맞춘 연결부(약 500줄): agent 선택, 메시지, 결정 모양, 채팅, 진행 표시
  - 화면 전부
- **엔진이 쓰는 `tasks` 표:** id, title, project_path, status, updated_at을 쓰고, `pazmo_*` 표들이 이 표를 참조한다.

## 결정 (1단계)

1. **켜는 방법.**
   - `start --lean`과 `up --lean`으로 새 Office를 켠다. 기본값은 지금처럼 Claw다.
   - 새 Office는 데이터 디렉터리 아래 `lean/office.sqlite`를 쓴다. `claw/claw.sqlite`는 건드리지 않는다.
   - 같은 프로젝트에서 두 Office를 동시에 켜지 않는다. 기존 시작 잠금 규칙을 따른다.
2. **서버.**
   - Node 내장 기능만 쓴다(`node:http`, `node:sqlite`). npm 의존성과 빌드 단계가 없다.
   - `127.0.0.1`에만 열린다.
   - 접속은 `monitor`가 주는 일회용 주소로 세션 쿠키를 받는 방식이다. 지금 Office처럼 사용자가 키를 입력하지 않는다.
   - 쓰기 요청에는 세션 CSRF를 요구한다.
3. **저장.**
   - `tasks`: 엔진이 쓰는 칸(id, title, project_path, status, updated_at)에 `body`, `agent_id`, `risk`, `created_at`을 더한다.
   - `agents`: id, name, `work_runner`, `review_runner`, 만든 시각.
     - 실행기 값은 CLI(codex|claude), 모델, effort다.
   - `task_events`: 작업별 진행 기록이다.
   - 엔진 표(`pazmo_*`)는 지금 정의를 그대로 쓴다.
4. **agent.**
   - 처음 켤 때, 준비된 CLI로 "기본 agent" 하나를 만든다. 작업 실행기와 리뷰 실행기는 같은 값으로 시작한다.
   - 추가, 이름 변경, 실행기 변경(작업·리뷰 따로), 삭제를 할 수 있다.
   - 맡은 작업이 진행 중인 agent는 삭제할 수 없다. 마지막 남은 agent도 삭제할 수 없다.
   - 실행기 검증은 지금 규칙을 따른다: 설치·로그인된 CLI만, 그 CLI의 모델·effort 목록 안에서만 고를 수 있다.
5. **작업 실행.**
   - 작업을 만들 때 agent를 고른다. 기본 agent가 미리 선택돼 있다.
   - kit 단계 중 기획(PM)·설계(Lead)·구현(Engineer)은 그 agent의 **작업 실행기**로 돌리고, 리뷰(Reviewer)는 **리뷰 실행기**로 돌린다.
   - 지금처럼 한 번에 한 작업만 실행하고, 나머지는 "대기"에 둔다.
   - 결정 규칙(G1·질문·G4·피드백 승인), 격리 실행, 검증, 인도는 지금 엔진 그대로다.
6. **화면.** 빌드 없는 HTML과 작은 JS로 만들고, 3초마다 새로 고친다. 밝은/어두운 테마와 ko/en을 지원한다.
   - **Tasks:** 열은 대기·진행·결정 대기·완료·취소다. 카드에는 제목, agent, 단계 진행(기획·설계·구현·리뷰 중 현재 단계), 위험도가 보인다. [새 작업]이 있다.
   - **작업 상세:** 진행 기록, 이 작업의 결정(바로 답하기), 변경 내용(diff), 결과 요약, 단계별 실행기·모델·버전, 인도 위치, [취소]가 있다.
   - **Decisions:** 모든 작업의 답할 것을 한곳에 모은다. 선택지·메모·피드백 승인은 지금 규칙 그대로다.
   - **Agents:** 목록, 추가, 이름 변경, 실행기 2종 변경, 삭제가 있다.
   - 확인은 화면 안에서 한다. 브라우저 기본 대화상자는 쓰지 않는다.
7. **이번에 없는 것:**
   - 팀 허브 화면(2단계)
   - 채팅
   - 하위 작업 화면
   - 회의
   - 대시보드
   - 픽셀 사무실
   - 동시 실행
   - 기존 데이터 옮기기

## 실패 처리

| 상황 | 동작 |
|---|---|
| 준비된 CLI가 없음 | 첫 실행이 `LOGIN_REQUIRED`로 멈추고 로그인 방법을 안내한다(지금 `up`과 같음). |
| 작업을 만들었는데 agent 실행기가 더는 쓸 수 없음 | 작업은 시작하지 않고 "agent 실행기를 확인하세요"를 보인다. |
| 진행 중 agent 삭제 시도 | 거부하고 "진행 중인 작업이 있습니다"를 보인다. |
| CSRF·세션 없음 | 403 / 401 |
| 같은 프로젝트에 Claw Office가 켜져 있음 | `--lean` 시작을 거부하고 먼저 멈추라고 안내한다. |

## 검증 (V17)

- 자동 시험:
  - 저장: 표 생성, 기본 agent
  - agent: 추가, 이름 변경, 실행기 검증, 진행 중 삭제 거부, 마지막 삭제 거부
  - 작업: 만들기, 대기열, 단계별 실행기 선택(리뷰만 다른 실행기)
  - 결정 답하기
  - 세션·CSRF, `127.0.0.1` 경계
  - 화면: 기본 대화상자 없음, 이스케이프
- 기존 시험(엔진·허브·Claw Office)은 모두 통과해야 한다.
- 실제 확인: app-be에서 `up --lean`으로 켜서 다음을 해 본다.
  1. 작업 하나를 만든다.
  2. 기획 → G1 답 → 구현 → 리뷰(다른 실행기) → G4 → 인도까지 돈다.
  3. agent를 추가·이름 변경·삭제한다.
- 보안을 포함한 브랜치 리뷰를 1회 한다.

## 대안과 복구

- **Claw 걷어내기(A), 지금대로(C):** 사용자가 B를 택했다.
- **역할 agent(①):** 사용자가 작업 agent를 택했다.
- **복구:** 1단계는 옵션(`--lean`)이라 기본 동작은 그대로다. 새 저장 파일만 쓰므로 기존 데이터는 바뀌지 않는다.
