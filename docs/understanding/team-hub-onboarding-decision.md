## 사용자 요청 (2026-10-15)

Fusion 허브를 실제로 쓰면서 Office 연결이 번거롭다고 했다. 지금 순서는 이렇다.
1. 허브에 레포를 등록한다.
2. 연결 명령을 만든다.
3. `<이 레포의 로컬 경로>`를 바꿔 넣는다.
4. 터미널에서 `node …/bin/pazmo-office.mjs hub-link`를 실행한다. `pazmo-office`는 설치된 명령이 아니다.

사용자는 "클릭 한 번이나 복사 붙여넣기만 해서 되도록" 해 달라고 했고, "개선 먼저 하고, 최대한 Flow를 단순화하고, Office 사용도 바로 할 수 있도록 한 상태로 테스트하자"고 했다.

## 결정

1. **허브 시작 화면.**
   - 초대·기기 링크로 처음 들어온 직후와 메뉴 **내 Office 연결**에서 세 단계 안내를 보여 준다.
     - ① 내 PC에서 Office 켜기(현재 실행 방법 안내. C가 끝나면 그 방법으로 바꾼다)
     - ② **연결 문자열 만들기 → [복사]**
     - ③ 다른 레포 담당자에게 일 보내기(Office의 팀 허브로 보내기)
   - 레포 화면의 레포별 "내 Office 연결 명령 만들기"는 이 화면으로 안내한다.
2. **연결 문자열(팀원 단위).**
   - 허브가 그 팀원에게 일회용 코드를 발급한다. 10분 동안 한 번만 쓸 수 있고, 저장은 해시로만 한다.
   - 형식은 `https://<허브 공개 주소>/connect#c=<코드>`다. 사내망 허브는 `&fp=<CA 지문>`을 붙인다.
   - `#` 뒤는 브라우저가 서버로 보내지 않는다. `/connect`를 브라우저로 열면 "이 문자열을 Office 상단의 팀 허브에 붙여넣으세요"만 보여 준다.
3. **짝 맺기 규칙.** Office가 코드와 자기 git origin(정규화한 host/path)을 보내면 허브는 이렇게 처리한다.
   - 그 origin의 레포가 있고 이 팀원이 담당자면, 그 레포에 연결한다.
   - 레포가 없으면, origin 끝부분 이름(예: `eevee-be`)으로 등록하고 이 팀원을 담당자로 둔 뒤 연결한다. 레포 등록 권한은 지금과 같아서, 모든 팀원이 레포를 등록할 수 있다.
   - 레포가 있는데 담당자가 아니면 거부하고 "이 레포의 담당자나 관리자에게 담당자 추가를 요청하세요"를 돌려준다. 코드는 쓰이지 않은 채 남는다.
   - 같은 (팀원, 레포)의 이전 연결은 지금처럼 회수된다.
   - 기존 레포 단위 연결 코드도 계속 받는다.
4. **Office 상단 "팀 허브" 버튼과 연결 창.**
   - 버튼은 상태를 표시한다. 연결 안 됨 / 연결됨(허브 호스트 · 내 이름 · 레포) / 옛 허브.
   - 창에는 붙여넣기 칸, **[연결]**, **[연결 해제]**(화면 안 확인 한 번), **[허브 열기]**가 있다.
   - 연결은 Office 로컬 API `POST /api/hub/link`(세션 CSRF)로 한다. Office 서버가 자기 프로젝트의 origin으로 짝을 맺고, 토큰은 서버의 데이터 디렉터리에만 0600으로 저장한다.
   - live Office는 5초 안에 허브에 붙는다. live가 아니면 "실행 모드에서만 연결됩니다"를 보여 준다.
   - 해제는 `POST /api/hub/unlink`(CSRF)다.
5. **터미널 명령.** `hub-link --project <경로> --connect "<문자열>"`을 받는다. 기존 `--hub/--code/--fingerprint` 형식도 그대로 동작한다.
6. **경계는 그대로다.**
   - Office는 `127.0.0.1`에만 열린다. 허브는 Office로 접속하지 않는다.
   - 연결은 사람이 문자열을 붙여넣고 누를 때만 일어난다. 웹페이지가 Office를 직접 부르는 방식은 쓰지 않는다.
   - 연결 토큰의 권한(D16–D19)은 바뀌지 않는다.

## 실패 처리

| 상황 | 동작 |
|---|---|
| 문자열 형식이 틀림 | 연결 창에 "연결 문자열 형식이 아닙니다"를 보여 준다. 허브에 요청하지 않는다. |
| 코드 만료·이미 사용 | "연결 문자열이 만료됐습니다. 허브의 내 Office 연결에서 새로 만드세요." |
| 담당자가 아닌 레포 | 위 결정 3의 안내를 보여 준다. 코드는 그대로 남는다. |
| git origin이 없거나 해석 불가 | "이 프로젝트에 git origin 원격 주소가 없습니다"를 보여 준다. |
| 공인 인증서가 아닌데 지문이 없음 | `HUB_TLS_UNTRUSTED` 안내를 보여 준다. 사내망 허브 문자열에는 지문이 들어 있다. |
| CSRF 없음 | 403. 화면은 항상 세션 토큰을 보낸다. |
| 이미 다른 허브에 연결됨 | 확인 칸에 "기존 연결(허브)을 이 연결로 바꿉니다"를 띄우고 진행한다. |

## 범위

- **이번(A):**
  - 허브: 시작 화면, 팀원 단위 연결 코드·문자열, `/connect` 안내 화면, 짝 맺기 시 레포 찾기·자동 등록
  - Office: 로컬 API `link`/`unlink`, 상단 버튼과 연결 창
  - CLI: `--connect` 옵션
  - 사용 안내
- **다음:** B(캐릭터 정리), 그 뒤 Fusion 실제 확인, C(공개 npm 설치)
- **제외:**
  - 웹페이지가 로컬 Office를 직접 부르는 원클릭 연결
  - 회사 SSO
  - 팀원 YAML
  - 특정 사람 지정 보내기
  - 레포 이름 자동 충돌 처리. 이름이 겹치면 `-2`를 붙인다(ASSUMED).

## 검증 (V14)

- 자동 테스트로 확인한다.
  - 허브:
    - 팀원 단위 코드 발급·해시·만료·1회
    - origin으로 레포 찾기, 자동 등록·담당자 지정
    - 담당자 아님 거부(코드 유지), 이름 충돌
    - 기존 레포 단위 코드 회귀, `/connect` 화면
  - Office:
    - 연결 문자열 해석
    - 로컬 API CSRF·실패 문구
    - 해제
    - 기존 연결 교체
  - 화면(vitest): 상단 버튼 상태, 연결 창, 브라우저 기본 대화상자 없음
- 기존 테스트는 전부 통과해야 한다. Office `127.0.0.1` 단언도 유지한다.
- 실제 확인은 B 다음에 Fusion 허브에서 한다.
  1. "테스트" 팀원을 초대하고 다른 브라우저로 합류한다.
  2. 시작 화면에서 문자열을 복사한다.
  3. 시험 Office 상단에 붙여넣어 연결한다. 레포는 자동 등록된다.
  4. eevee-be에서 보내기 → 테스트 수락 → 취소를 한 바퀴 돈다.
- 보안을 포함한 브랜치 전체 리뷰 1회. 결과는 X/X로 보고한다.

## 대안과 복구

- **레포 단위 유지:** 단계가 하나 더 남아 택하지 않았다.
- **원클릭(허브 페이지가 로컬 Office 호출):** 아무 웹사이트나 내 Office를 엉뚱한 허브에 붙일 수 있는 구멍이 생기고, "허브는 Office로 들어오지 않는다" 경계가 깨져 택하지 않았다.
- **회사 SSO + 팀원 YAML:** 사용자가 초대 링크와 SQLite를 유지하기로 해서 택하지 않았다.
- **복구:** 레포 단위 코드와 기존 CLI 형식을 남기므로, 새 경로와 화면을 빼면 지금 방식으로 돌아간다.
