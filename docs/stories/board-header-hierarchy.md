# Story: 보드 맨 위에서 보기 전환, 프로젝트 필터, 주요 버튼이 한눈에 구분된다

## Goal
1. As-is:
   - [새 프로젝트]와 각 프로젝트의 [새 Story]가 회색 테두리의 보조 버튼(`btn ghost`)이다. 바로 옆의 필터 토글(내 Story만, 취소한 것도 보기)과 모양이 거의 같아서 주요 동작으로 보이지 않는다 (`src/hub/board-pages.ts:275`, `:298`, `src/hub/pages.ts:91`).
   - 프로젝트 구역 머리는 `<h2>프로젝트 이름</h2>[새 Story]`뿐이다. 그 글자가 프로젝트 이름이라는 표시가 없다 (`src/hub/board-pages.ts:304`).
   - 맨 위 순서가 필터 토글과 [새 프로젝트] → 보기 탭(Story 보드 / 모든 Task) → 프로젝트 칩이다. 고른 칩은 진한 글자색으로 꽉 채워 그린다(`--fg` 배경, `src/hub/pages.ts:109`). 고른 탭은 회색 판 위에 흰 칸과 밑줄 3px이라 칩보다 약하다. 그래서 상위인 보기 전환이 하위인 필터보다 약해 보이고, 필터가 탭 위에 있다.
2. To-be:
   - 1줄(페이지 단계): 왼쪽에 보기 탭 "Story 보드 | 모든 Task"가 페이지 제목처럼 크게 있고, 줄 전체에 밑선이 있다. 오른쪽 끝에 [+ 새 프로젝트]가 채운 주요 버튼(`--accent` 배경)으로 있다.
   - 2줄(필터 단계): "프로젝트" 레이블 뒤에 프로젝트 칩, 그 뒤에 내 Story만과 취소한 것도 보기 토글이 있다. 칩과 토글은 1줄보다 작다(마우스 36px, 터치 44px). 고른 칩은 고른 토글과 같은 모양이다(옅은 파랑 배경과 `--accent` 테두리).
   - 프로젝트 구역 머리는 작은 회색 레이블 "프로젝트" 아래에 이름(h2)과 [+ 새 Story]가 있다. [+ 새 Story]는 채운 주요 버튼이다.
3. Unchanged:
   - 누가 무엇을 보는지: [새 프로젝트]는 웹 기획을 쓰는 Hub에서만, [새 Story]는 그 프로젝트의 모든 레포 담당자에게만 보인다 (`src/hub/server.ts:252-253`).
   - 모든 링크 주소와 필터 보존: 탭은 필터를, 칩은 탭과 토글을, 토글은 프로젝트를 그대로 가지고 간다. 탭의 마크업(`<nav class="tabs" aria-label="보드 보기">…`)과 칩의 마크업(`<nav class="chips" aria-label="프로젝트">…`), 칩의 개수와 표시(멈춤 네모, 승인 대기 동그라미).
   - 프로젝트가 하나면 칩 줄이 없다(D44). 확인할 것 상자, 프로젝트 안의 단계·레인·카드, 빈 상태 문구, 위쪽 머리글(보드/팀, 자동으로 일하기, 내 Mac).
   - 다른 화면(새 프로젝트, 새 Story, Story, 기획 화면)의 버튼과 브레드크럼.

## Decisions
- D1. 버튼을 무엇으로 바꿀까 ("다른 모양이나 색")
  - Options: 채운 주요 버튼(`.btn`, `--accent` 배경) / 파란 테두리 보조 버튼 / 아이콘만 추가
  - Pick: 채운 주요 버튼에 "+" 표시를 붙인다. 디자인 체크리스트 규칙 5가 `--accent`를 "주요 동작(채운 버튼)"에만 쓰라고 하고(`docs/solutions/conventions/hub-design-checklist.md` 규칙 5), Hub의 다른 주요 동작도 이미 `.btn`이다 (`src/hub/pages.ts:90`). "+"는 새로 만드는 동작이라는 모양이고, 읽어 주는 이름에는 넣지 않는다.
- D2. 전체 보기에서 프로젝트마다 [새 Story]가 있으면 채운 버튼이 여러 개다
  - Options: 모두 채운 버튼 / [새 Story]만 채우고 [새 프로젝트]는 파란 테두리
  - Pick: 모두 채운다. 요청이 두 버튼 모두를 주요 동작으로 보이라고 했고, 버튼마다 자기 구역(페이지 머리, 프로젝트 머리)에서 하나뿐인 주요 동작이다. 전체 보기에서 Story가 없는 프로젝트는 이미 한 줄로 접혀 버튼이 없다 (`src/hub/board-pages.ts:291-295`).
- D3. 보기 탭과 프로젝트 칩 중 무엇이 위인가
  - Options: 탭이 페이지 단계, 칩은 토글과 같은 필터 단계 / 프로젝트가 위(범위), 탭이 아래
  - Pick: 탭이 위다. 숨은 h1이 탭 이름("Story 보드"/"모든 Task")이라 탭이 곧 페이지 제목이고 (`src/hub/board-pages.ts:275`), 칩은 토글과 같은 `Filters`의 `?project=` 값이다 (`src/hub/board-pages.ts:59`, `:257`).
- D4. "프로젝트임을 알려 주세요"를 어떻게
  - Options: 이름 위 작은 레이블 / 이름 앞 태그 / "프로젝트: 이름" 한 줄
  - Pick: 이름 위 작은 레이블(카드의 "Story #1" 레이블과 같은 `.kind` 모양, `src/hub/pages.ts:192`). 제목(h2)은 이름 그대로 두어 읽는 순서와 기존 검사가 바뀌지 않는다. 필터 줄의 칩 앞에도 같은 말 "프로젝트"를 레이블로 붙인다.
- Copies: 머리(`titlebar`)와 프로젝트 구역(`projectsOf`)은 Story 보드(`/`)와 모든 Task(`/tasks`)가 함께 쓴다. 두 보드 모두 바뀐다. 스타일은 `src/hub/pages.ts`의 `STYLE` 하나다. 디자인 체크리스트(`docs/solutions/conventions/hub-design-checklist.md`)에 "페이지 단계 탭이 필터보다 위" 규칙과 칩·토글 크기를 적는다.

## MUST
- M1. 두 버튼이 주요 동작으로 보인다
  1. [새 프로젝트]와 [새 Story]는 `--accent`로 채운 버튼이고, 글자 앞에 "+"가 있다. 읽어 주는 이름은 "새 프로젝트", "새 Story" 그대로다.
  2. 라이트·다크 두 테마에서 버튼 글자 대비가 4.5:1 이상이다.
- M2. 프로젝트 이름에 레이블이 있다
  1. 각 프로젝트 구역에서 이름 바로 위에 "프로젝트" 레이블이 보인다. 두 보드 모두.
- M3. 보기 전환과 필터의 위계가 구분된다
  1. 맨 위 1줄에 보기 탭과 [새 프로젝트]가 있고, 그 아래 2줄에 프로젝트 칩("프로젝트" 레이블과 함께)과 두 토글이 있다.
  2. 탭 글자가 칩과 토글 글자보다 크고, 칩과 토글은 마우스에서 36px, 터치에서 44px 높이다.
  3. 고른 칩은 진한 색으로 꽉 채우지 않고, 고른 토글과 같은 옅은 파랑 배경과 `--accent` 테두리다.
  4. 320px부터 1360px까지 두 테마에서 잘리거나 겹치는 것이 없다.

## OUT
- O1. 위쪽 머리글(보드/팀 메뉴, 자동으로 일하기, 내 Mac)의 모양: 요청은 보드 화면 안의 위계다.
- O2. 다른 화면의 브레드크럼에 있는 프로젝트 이름: 요청은 [새 Story] 옆 이름이다.
- O3. 단계·레인·카드의 모양: 요청 밖이다.
