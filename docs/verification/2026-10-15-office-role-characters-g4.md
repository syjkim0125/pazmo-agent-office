# 2026-10-15 Office 캐릭터 역할 중심 정리 (B) 실제 확인과 G4

Story: M13 · V15 · D21. 검증 기록: [2026-10-15-office-role-characters.md](2026-10-15-office-role-characters.md). U12·A와 함께 한 번에 확인했다(PR syjkim0125/pazmo-agent-office#23 → #24 → #25).

## 실제 확인 (2026-10-15)

- app-be Office(claw 엔진)를 B 빌드로 다시 시작했다(사용자 허락). 영어·밝은 테마에서 방 3개와 PM·Lead·Engineer·Reviewer 4명만 보였고, 상단 Team hub는 connected였다.
- 같은 날 OpenShift 실제 확인(합류·붙여넣기 연결·보내기·수락·취소)도 이 빌드의 두 Office로 했다.
- 확인하지 않은 것: 어두운 테마, 한국어 이름, 캐릭터 상세의 원래 이름.

## G4 (2026-10-15~16, 사용자 답변)

질문(2026-10-15, 컨트롤러가 G4 설명 페이지와 대화로 냄): ① A 연결 동작, ② 실패 시 기존 연결·접속 방향(불변 조건), ③ B 캐릭터 동작, ④ 증거 범위, ⑤ B 기본값 결정이 원한 것과 맞는지. 사용자가 "G4는 너가 알려줘"라고 해서 컨트롤러가 각 질문의 맞는 이해를 정리해 보였고, 답은 사용자가 했다.

> 1~4번 맞음. 5번 맞아.

| 항목 | 평가 |
| - | - |
| 동작 | 충분하지만 자기 말로 쓴 답은 아니다. 컨트롤러가 정리한 이해(origin으로 레포 찾기·자동 등록·담당자 아님 거부, 역할 4명만 역할 이름으로 표시)를 "맞음"으로 확인했다. 같은 흐름을 실제 확인에서 직접 했다. |
| 불변 조건·실패 동작 | 충분하지만 자기 말로 쓴 답은 아니다. 실패 시 기존 연결 유지, 허브가 Office로 먼저 접속하지 않음, 숨김은 표시만 바뀌고 DB는 그대로임을 확인했다. |
| 증거 범위 | 충분. 확인하지 않은 것(어두운 테마, 한국어 이름, 다른 사람의 실제 PC, 노트북 IP 변경)과 확인한 것(OpenShift 실제 확인, 재배포 뒤 연결 유지, app-be 실제 화면, 자동 시험)을 확인했다. |
| B 결정(D21) | 일괄 진행 지시로 기본값을 정한 결정 1–6이 원한 것과 맞다고 확인했다(사후 확인). |

남는 한계: 답이 컨트롤러 설명을 확인하는 형태라 자기 말 답보다 근거가 약하다. 사용자는 이 평가를 본 뒤 2026-10-16 "피드백 확인 후 승인"이라고 답했다(D13 방식). 이 답이 G4다.
