Scope: U9, Story M8, V10, D16.

이 기록은 G4나 전체 Story 완료를 주장하지 않는다. 커밋 전 작업 트리 기준이다. **다른 사람의 실제 PC, 회사 IT 정책, 여러 날 운영은 확인하지 않았다.** 그 전에는 "다중 PC 검증 완료"로 보고하지 않는다.

## 무엇이 만들어졌나

- **허브(`pazmo-office hub`):** 게시판이자 우체국이다. 팀원·초대·레포·담당자·요청·진행 스냅샷·답변만 저장하고 AI, 로그인, 인도물, VM에는 닿지 않는다. 자체 CA와 서버 인증서로 HTTPS만 제공한다. 데이터는 Office와 분리된 `team-hub/` 디렉터리의 SQLite에 있다.
- **Office 연결(`hub-link`, `hub-unlink`):** live Office가 허브로 5초마다 나가는 HTTPS 조회를 한다. 수락된 요청을 기존 요청 등록 경로로 넣고, 진행을 스냅샷 하나로 올리고, 요청자의 답변·취소를 기존 경로로 전달한다. Office는 계속 `127.0.0.1`에만 열린다.
- **권한:** 요청은 누구나, 수락과 Office 연결은 레포 담당자만, 질문·G1 답변은 요청자만, 초대와 회수는 관리자만 한다. G4와 인도는 맡은 사람의 Office에서만 한다.

**리뷰에서 찾아 고친 보안 관련 결함** (각각 테스트를 먼저 쓰고 고쳤다):
- **Origin:null:** `Referrer-Policy: no-referrer`가 브라우저에 `Origin: null`을 보내게 해 모든 실제 POST가 403이었다. `same-origin`으로 바꾸고 `null` Origin 거부를 테스트에 넣었다.
- **CA 다중 인증서 고정 우회:** 지문은 첫 인증서만 확인하는데 PEM 안의 모든 인증서가 신뢰됐다. 같은 LAN의 공격자가 짝 맺기 때 연결 토큰과 지속 신뢰를 얻을 수 있었다(실험으로 확인). 이제 정확히 인증서 한 개, `ca === true`만 받고 다시 인코딩한 단일 인증서를 저장한다.
- **LibreSSL 명시 곡선 키:** LibreSSL의 `req -newkey ec` 키가 Node/OpenSSL 3에서 거부됐다. CA·서버 키를 Node(`prime256v1`, 0600 생성)에서 만들고 openssl은 서명에만 쓴다. 키 권한 창도 함께 없어졌다.
- **CA 이름 제한:** 탈취된 CA 키로 팀원 브라우저가 임의 사이트에 속을 수 있었다. 사설 IPv4 대역(10/8, 172.16/12, 192.168/16, 127/8)과 설정한 이름만 허용하는 nameConstraints를 넣었다.
- **담당자의 요청자 게이트 답변:** 맡은 사람이 자기 Office에서 요청자의 질문·G1에 답할 수 있었다. `HUB_REQUESTER_ONLY`로 허브 경유 답변만 받는다. 로컬 operator API(운영자 키 보유자)는 자기 PC의 관리자 우회 경로로 남긴다.
- **origin URL 자격증명:** `user:token@`가 붙은 git origin이 허브로 갔다. 정규화한 host/path만 보낸다.
- **완료 스냅샷의 diff 누락:** 종료 스냅샷이 diff를 null로 덮어써 허브에서 변경 내용이 사라졌다. 이전 diff와 요약을 유지한다.
- **재연결 시 Office 중복:** 같은 팀원·레포로 두 번째 Office를 연결하면 작업이 중복되고 취소되지 않았다. 로컬에 매핑되지 않은 배정은 건너뛴다.
- **바이트 제한:** 허브는 16000자, Office는 16384바이트를 받아 한글 요청이 조용히 멈췄다. 요청은 UTF-8 16384바이트로 맞췄고, 스냅샷은 UTF-8 바이트로 잘라 전체 900 KiB를 넘지 않게 했다.

그 밖에 리뷰가 잡아 고친 것: 세션 쿠키 갱신(30일 슬라이딩), 본문 읽기 전 세션 확인, 늦게 도착한 bind가 중지 신호를 다시 여는 문제, 서버 인증서가 현재 CA로 검증되지 않으면 재발급, CA 만료 임박 시 명시적 오류, 스냅샷이 G4 증거 JSON을 담던 문제(G4 요약은 사람이 읽는 부분만), 한 배정의 실패가 다른 배정의 동기화를 막던 문제.

## 실제 확인 (2026-10-12, Mac 한 대)

허브와 eevee-be Office를 같은 Mac에서 돌리고, 다른 브라우저 프로필로 팀원 "테스트"를 맡았다.

| 단계 | 결과 |
| - | - |
| 1. 허브를 사내망 IP에 시작 | 사내망 IPv4로 `hub` 시작. 관리자 초대 링크가 한 번 출력됐다. 이후 아래 "발견"의 IP 변경으로 두 번 더 재시작해 최종 192.168.12.141에서 확인했다. |
| 2. CA 신뢰 | 사용자가 직접 신뢰했고, 이후 브라우저가 경고 없이 열렸다. 단, `security verify-cert`는 계속 `CSSMERR_TP_NOT_TRUSTED`였고 login 키체인에서 CA가 검색되지 않았다. 브라우저 자체 저장소에 신뢰한 것으로 보이며, 시스템 키체인 신뢰 절차(`security add-trusted-cert`)는 실제로 검증하지 못했다. |
| 3. 레포 등록·Office 연결 | eevee-be를 등록하고 `hub-link`로 짝을 맺었다. CA는 1개 인증서로 고정됐다. |
| 4. 요청 | 팀원 "테스트"가 허브에서 eevee-be 요청을 올렸다. |
| 5. 수락 | 관리자가 수락했다(사용자 요청에 따라 컨트롤러가 `HubStore`로 수락). Office가 5초 안에 요청을 접수했다. |
| 6. PM 범위 G1 | 요청자 프로필이 허브에서 답했다. Office 기록에 출처 `hub:<id>`, revision 4로 남았다. |
| 7. 작업 G1 | 맡은 사람이 Office에서 답했다. 처음 시도는 다른 Office 화면으로 갔고(아래 발견), 컨트롤러가 채운 답을 사용자가 제출했다. |
| 8. 구현·리뷰 | Developer, Reviewer 진행. |
| 9. G4 | 사용자가 Office에서 직접 답했다. 평가는 "보완 필요", 이후 "피드백 확인 후 승인"(D13). |
| 10. 인도 | 2026-10-12 18:23:02 `delivery-gui37b`로 인도됐다. |
| 11. 허브 | 상태 `done`. diff, 4줄 요약, 역할별 실행기(모두 claude)가 표시됐다. |

- 원본 eevee-be 저장소는 바뀌지 않았다.
- 허브만으로는 결과물이 나가지 않았다. 인도는 맡은 사람의 로컬 G4 뒤에만 일어났다.
- 이 확인은 같은 Mac의 한 사용자가 두 역할을 오간 것이다. 요청자와 맡은 사람이 서로 다른 PC·사람인 경우를 대신하지 않는다.

## 알아 둘 판단과 남긴 minor

**보류한 판단** (장부의 parked):
- 두 번째 Office로 다시 짝을 맺으면 첫 연결이 회수되고, 요청이 나중에 취소돼도 첫 Office의 로컬 작업은 계속 돈다. 허브에서 Office로 보내는 채널이 설계상 없어 감지할 수 없다. **옮기기 전에 진행 중인 일을 반납하거나 취소한다.** 남으면 맡은 사람이 직접 취소한다.
- 허브는 질문별 답변 형식(4096자, 번호)을 미리 검증하지 않는다. 실패는 "전달 실패"와 Office의 이유로 보인다.
- 약 7,200자와 바이트 한도 사이의 한글 요청은 일반 413 메시지를 본다. 취소된 요청은 마지막 diff를 계속 보여 준다. C1·bidi 제어문자는 로그에서 제거하지 않는다. `.git.git` 원격은 짝 맺기에 실패한다. 자식 작업의 요청자 결정(현재 생성되지 않음)은 허브에 보이되 답할 수 없다.

**미룬 minor** (요약):
- 연결 쪽에 "같은 원인이면 2회 후 멈춤" 상한이 없다. 401이 계속 오면 5초마다 다시 조회하고, 결정적인 제출 실패도 5초마다 반복한다.
- `stop()`은 진행 중인 동기화 패스를 기다리지 않는다. 첫 패스는 주기 하나를 기다린다.
- 허브 CA는 회전하지 않는다. 만료 30일 전이면 `HUB_CA_EXPIRING`으로 멈춘다(TLS 디렉터리 삭제 후 재신뢰). CA 이름을 바꾸면 `HUB_CA_NAME_CHANGED`로 멈춘다. IP 변경은 사설 대역 안이면 CA를 유지한다.
- 해제·회수 경로(링크 코드 만료, 팀원 회수 후 열린 배정, 비관리자 기기 회수 등)의 일부 테스트가 없다. 팀원을 회수해도 그 사람이 맡은 열린 배정은 열려 있다.
- Host/Origin의 포트 443·대소문자 정규화, 405의 `Allow` 헤더, `__Host-` 쿠키 접두사, `SameSite=Strict` 첫 이동에서 로그아웃 화면이 보이는 것(새로 고침 안내 추가).
- 복사 버튼: 실패 경로가 성공 타이머를 지우지 않고, 실패 라벨이 되돌아오지 않는다.
- 스냅샷 `fitBudget`에 최종 하드 검사가 없고, 새 `pazmo_hub_answers` 열의 마이그레이션이 없다(미출시).
- 일부 상태 표시: 맡은 사람의 게이트만 대기 중이어도 "waiting", 자식이 취소되면 루트가 done으로 넘어가지 않는 경우, 인도 후 diff가 사라지는 경우(완료 스냅샷은 유지).

## Story·Task 검사

Story checker와 Task checker의 종료 코드는 이 문서를 쓴 뒤 실행해 작업 보고에 적었다. exit 0만 통과다.
