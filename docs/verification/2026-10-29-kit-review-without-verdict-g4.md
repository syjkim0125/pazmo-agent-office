# 2026-10-29 판정 없는 리뷰를 kit에 needs_changes로 남기지 않기 G4

Story: M4 · D26 · D27(ASSUMED). 검증 기록: [2026-10-29-kit-review-without-verdict.md](2026-10-29-kit-review-without-verdict.md). PR syjkim0125/pazmo-agent-office#42. kit graph: `.ai-workflow/runs/U23-kit-review-without-verdict.json`(상태 `g4`).

## 질문과 답 (2026-10-29)

컨트롤러는 먼저 G4 설명 페이지("판정 없는 리뷰 기록")와 대화로 증거를 보였다. 증거는 kit 기록의 전후, kit가 실패 기록의 verdict를 검사하지 않는 근거(`cli.mjs:104`), D27의 기록 방식과 고르지 않은 방식, 시험·리뷰 결과, 확인하지 못한 것이다. 그다음 세 질문과 선택지를 냈다. 사용자는 "승인후 머지"라고만 답했고 세 질문에는 답하지 않았다. 그래서 컨트롤러는 D13에 따라 피드백(답 초안)을 보이고 확인을 물었다. 사용자는 초안을 고치지 않고 이렇게 답했다.

> 응 피드빅 확인 후 승인으로 기록해

사용자가 확인한 답(컨트롤러 초안 그대로):

1. 동작: 리뷰 실행기가 보고서 없이 끝나면(시간 초과처럼 판정이 없는 다른 결과도) kit 리뷰어 run에는 "No review verdict for the submitted snapshot."와 관찰만 남는다. `needs_changes`와 `reviewedRevision`은 적지 않는다. 노드는 `failed`, `action: "human"`이고, 실행기 실패면 피드백에 `REVIEW_RUNNER_FAILED`가 들어간다. Office 쪽 멈춤·이유·자동 수정 횟수는 #35 그대로다.
2. 규칙과 실패: `needs_changes`는 리뷰어가 보고서에서 실제로 고칠 것을 찾았을 때(Office 결과 fail)만 쓴다. 판정 없는 리뷰는 kit 노드가 실패라 역할 완료(`role-complete`)가 될 수 없고, 인도 영수증(`verifyCompletion`)은 완료된 제출의 verdict가 `pass`일 때만 만들어진다. 그래서 판정 없는 리뷰로는 인도까지 못 간다. kit는 통과 기록만 판정을 검사하므로 kit 파일은 그대로다.
3. 증거와 한계: 새 시험(실행기 실패·시간 초과 두 경우)이 고치기 전 `needs_changes`로 실패했고 고친 뒤 통과한다. 관련 3개 파일은 되돌리면 48/49, 적용하면 49/49, 전체 1093/1093, 타입 검사·Story 검사기 exit 0이다. 독립 리뷰 두 번 Approve였고, 리뷰어가 실제 kit `status`로 오류가 나지 않음을 확인했다. 확인하지 못한 것: 실제 실행기 오류로 이 경로를 거친 확인(안전장치 거절은 재현할 수 없음). 픽스처의 시간 초과는 `error: "TIMEOUT"`을 넣지 않지만 결과는 같다.

선택: ① 승인 후 머지. main 머지는 사용자가 직접 한다.
