# 2026-10-28 리뷰 실행기 오류를 리뷰 fail로 세지 않기 G4

Story: M4 · D25. 검증 기록: [2026-10-27-review-runner-failure.md](2026-10-27-review-runner-failure.md). PR syjkim0125/pazmo-agent-office#35. kit graph: `.ai-workflow/runs/U19-review-runner-failure.json`(상태 `g4`).

## 질문과 답 (2026-10-28)

컨트롤러가 G4 설명 페이지("리뷰 실행기 오류 분류", G4판)와 대화로 증거를 먼저 보였다. 증거는 U19 상태, main 대비 diff 통계, 제품 코드 diff 전문, 시험·리뷰 결과, 확인하지 못한 것이다. 그다음 세 질문과 선택지(① 승인 후 머지, ② 고친 뒤 다시 G4, ③ 머지하지 않음)를 냈다. 사용자가 "답 초안 너가 써줘 보고 고칠게"라고 해서 컨트롤러가 초안을 냈다. 사용자는 초안을 고치지 않고 이렇게 답했다.

> 피드백 확인 후 승인

사용자가 승인한 답(초안 그대로):

1. 동작: 리뷰 실행기(codex·claude CLI)가 API 오류·안전장치 거절·로그인 실패 같은 이유로 보고서 없이 0이 아닌 코드로 끝나면, 예전에는 리뷰 fail로 기록돼 구현을 다시 돌리고 자동 수정 1회를 썼다. 이제는 "판정 없음(unknown)"으로 기록되고 작업이 `REVIEW_RUNNER_FAILED`로 멈춰 사람에게 넘어온다. 엔지니어는 다시 돌지 않고 수정 횟수도 쓰지 않는다. lean Office에는 "하위 작업이 멈췄습니다: REVIEW_RUNNER_FAILED (작업 제목)"이 보이고, Claw Office에는 리뷰 판정 unknown과 대기 상태가 보인다. 등록 검사가 실패하면 예전처럼 fail이고 자동 수정 2회까지 돈다. 멈춘 작업은 지금은 취소 후 새로 만들어야 한다.
2. 규칙과 실패 동작: 판정이 없는 결과는 고칠 결함으로 세지 않는다. 리뷰 판정은 보고서에만 있고 보고서는 exit 0일 때만 읽으므로, 정상 종료한 exit≠0 리뷰에는 판정이 없다. unknown은 절대 G4나 인도로 가지 않고(모든 판정이 pass여야 G4), 자동 재실행도 없다. 멈춘 라운드에서 다시 시작하려 하면 거절된다. 시간 초과·중단·보고서를 못 읽은 경우는 예전처럼 `UNKNOWN_RESULT`로 멈춘다. 검사가 먼저 실패하고 그 뒤 리뷰 실행기가 실패하면 `CHECK_FAILED`가 아니라 `REVIEW_RUNNER_FAILED`로 멈추고, 실패한 검사 결과는 기록에 남는다.
3. 증거와 한계: verification 시험(관찰된 출력 그대로 → unknown, `REVIEW_RUNNER_FAILED`, 다시 시작 거절)과 coordinator 시험(kit 경로에서 엔지니어가 한 번만 돌고 멈춤, 고치기 전에는 다시 돌아 G4까지 감)이 확인했다. budgets 시험은 검사 실패로 실패 라운드를 만들도록 픽스처만 바꿨다. 고치기 전 56/58, 고친 뒤 58/58. 전체 927/929(부하로 인한 시작 시간 초과 2건, 따로 15/15). 타입 검사 0, 독립 리뷰 Approve. 확인하지 못한 것: 실제 실행기 오류가 이 경로를 지나는 실제 실행(안전장치 거절은 재현 불가), codex 오류 종료 코드, 멈춘 작업 다시 돌리기(후속).

선택: ① 승인 후 머지(main 머지는 사용자가 직접).

Story, diff, 시험과 비교했다.

| 항목 | 평가 |
