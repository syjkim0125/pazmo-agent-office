# 2026-10-30 모델 목록 조회 claude의 멈춤 유예 12초, lean 시작 대기 30초 G4

Story: M3 · M4 · D31. 검증 기록: [2026-10-30-discovery-stop-grace.md](2026-10-30-discovery-stop-grace.md). PR syjkim0125/pazmo-agent-office#51. kit graph: `.ai-workflow/runs/U26-discovery-stop-grace-replan-2.json`(상태 `g4`).

## 질문과 답 (2026-10-30)

컨트롤러는 먼저 설명 페이지("OAuth 갱신 잠금 사고" 6부)와 대화로 증거를 보였다. 증거는 PR #51의 변경 파일, 시험 결과(새·바꾼 시험 3개의 RED, 돌연변이 4/4, 전체 시험 1106/1106), 독립 리뷰 판정, 확인하지 못한 것이다. 그다음 세 질문(바뀐 동작, 지켜야 할 규칙과 실패 동작, 시험과 확인하지 못한 것)을 냈다. 사용자는 세 질문에 직접 답하지 않고 이렇게 지시했다.

> 설명해주고 작업한거 커밋하고 푸시하고 머지도 해

그래서 컨트롤러가 답을 쓰고(D13 방식), 지시대로 승인으로 기록한다. 사용자는 이 답을 기록 전에 보지 않았다.

1. 동작:
   - Office가 claude의 모델 목록을 물은 뒤 그 claude를 멈추는 순서는 입력 닫기 → 3초 → 프로세스 그룹 SIGTERM → **12초**(이전 2초) → SIGKILL → 2초다. 역할 실행(D28)과 같은 12초다.
   - 보통 claude는 입력을 닫으면 0.3초에 끝나므로 바뀌는 것이 없다.
   - 로그인 갱신 중인 claude는 SIGTERM 뒤 갱신을 최대 2초 기다리고 나간다. 바쁠 때는 끝나기까지 최대 9.1초가 걸렸다. 이제는 SIGKILL 전에 스스로 끝나 `~/.claude/.oauth_refresh.lock`을 푼다. 그래서 작업 만들기·계획 재개 바로 뒤의 계획 claude가 로그인에 실패하는 2026-10-23 사고가 이 자리에서 다시 나지 않는다.
   - 비용: 입력을 닫고 5초 뒤에도 살아 있는 claude가 있으면, 조회를 기다리는 요청이 최대 10초 더 기다린다. lean에서는 작업 만들기, 계획 재개 답, agent 실행기 저장, 실행기 목록이다. Claw에서는 실행기 상태 새로고침과 agent 저장 때 다시 조회하는 경우다.
   - live lean Office는 첫 조회 뒤에야 준비를 알리므로 시작 대기가 15초에서 **30초**로 늘었다. CLI 시험의 실행 한도도 그보다 길게 했다.
2. 규칙과 실패 경로:
   - 규칙: 사용자의 로그인을 쓰는 claude를 SIGKILL로 먼저 끝내지 않는다. SIGKILL은 입력 끝과 SIGTERM을 모두 무시하는 CLI에만, SIGTERM 12초 뒤에 쓴다.
   - SIGTERM까지 무시하는 claude는 입력을 닫고 15초에 SIGKILL된다. 멈춤 최악은 17초다.
   - 15초 동안 답하지 않는 claude는 조회만 최대 32초가 걸린다. lean 시작이 30초를 넘으면 "Office startup timed out"으로 끝난다. 그때 서비스가 나가면 조회 claude는 입력 끝을 받고, 아무도 SIGKILL하지 않으므로 잠금을 남기지 않는다. 사용자는 이 경우를 알고 30초로 두기로 했다(D31, "그대로").
   - 시작 중 서비스가 SIGTERM을 받아 10초 안에 나가면, 입력 끝과 SIGTERM을 모두 무시하는 CLI는 남을 수 있다. 그 구간이 2초에서 12초로 늘었다.
3. 증거와 한계:
   - 가짜 claude 시험(모두 고치기 전에 실패하는 것을 확인했다):
     - SIGTERM 뒤 11.999초에야 잠금을 푸는 claude가 풀고 끝난다.
     - SIGTERM도 무시하는 claude는 11.999초에 살아 있고 12초에 SIGKILL된다.
     - lean 시작 대기는 조회 멈춤 최악보다 10초 이상 길다.
   - 돌연변이 4/4를 잡았다. 전체 시험은 네 번 모두 1106/1106 exit 0이다(리뷰 전, 리뷰를 고친 뒤, main을 합친 뒤 두 번). 타입 검사와 Story 검사기는 exit 0이다. 독립 리뷰는 네 번 했다(1차 Changes needed → 2·3·4차 Ready).
   - 실제 근거는 2026-10-29 측정이다. 갱신 중 SIGTERM은 최대 9.1초가 걸렸고, 6초 SIGKILL은 잠금을 남겼다. 이번 변경으로 실제 claude를 새로 재지는 않았다.
   - 확인하지 못한 것:
     - 갱신 중인 claude가 입력 끝만으로 끝나는지, 갱신 중에 `initialize`에 답하는지
     - 바쁠 때 실제 lean 시작 시간
     - 조회 1단계의 `claude auth status`가 잠금을 잡는지. 후속 세션이 따로 쟀다(PR #52).

선택: 승인 후 머지. 사용자가 머지까지 맡겼다.
