# 2026-10-15 팀 허브 합류·연결 붙여넣기 (A) 실제 확인과 G4

Story: M12 · V14 · D20. 검증 기록: [2026-10-15-team-hub-onboarding.md](2026-10-15-team-hub-onboarding.md). U12·B와 함께 한 번에 확인했다(PR syjkim0125/pazmo-agent-office#23 → #24 → #25).

## 실제 확인 (2026-10-15, Fusion 허브)

- 허브를 A 코드로 다시 배포했다(사용자 허락, 사용자의 oc 세션). 파드 교체 뒤 `/healthz` 200, `/connect` 200, eevee-be Office 연결은 유지됐다.
- 사용자가 관리자 브라우저에서 "민호우" 초대 링크를 만들고 시크릿 창으로 합류했다. 시작 화면의 연결 문자열을 시험 Office(시험 레포)의 상단 팀 허브에 붙여넣어 연결했다. 허브에 없던 `hub-test-backend`가 민호우를 담당자로 자동 등록됐고, 이전 사내망 허브 연결은 교체됐다.
  - 처음에는 초대 링크를 붙여넣어 "연결 문자열 형식이 아닙니다"가 나왔다(의도된 거부). 화면 안내 개선은 다음 묶음으로 넘겼다.
- eevee-be Office에서 hub-test-backend로 요청을 보냈고(08:04 UTC), 민호우가 허브에서 수락하자 시험 Office에 작업이 생겼고(08:07), eevee-be에서 취소하자 보낸 기록과 시험 Office 작업이 모두 `cancelled`가 됐다(08:08).
- 확인하지 않은 것: 다른 사람의 실제 PC, 노트북 IP 변경, 어두운 테마, 한국어 이름.
- 발견: 시험 Office에 이전 허브에서 받은 10/13 작업 하나가 `pending`으로 남아 있다. 다음 묶음에서 확인한다.

A에 해당하는 것: 초대 합류 → 시작 화면 연결 문자열 → Office 상단 붙여넣기 연결, origin으로 레포 자동 등록, 기존 연결 교체, 초대 링크 거부.

## G4 (2026-10-15~16, 사용자 답변)

질문(2026-10-15, 컨트롤러가 G4 설명 페이지와 대화로 냄): ① A 연결 동작, ② 실패 시 기존 연결·접속 방향(불변 조건), ③ B 캐릭터 동작, ④ 증거 범위, ⑤ B 기본값 결정이 원한 것과 맞는지. 사용자가 "G4는 너가 알려줘"라고 해서 컨트롤러가 각 질문의 맞는 이해를 정리해 보였고, 답은 사용자가 했다.

> 1~4번 맞음. 5번 맞아.

| 항목 | 평가 |
| - | - |
| 동작 | 충분하지만 자기 말로 쓴 답은 아니다. 컨트롤러가 정리한 이해(origin으로 레포 찾기·자동 등록·담당자 아님 거부, 역할 4명만 역할 이름으로 표시)를 "맞음"으로 확인했다. 같은 흐름을 실제 확인에서 직접 했다. |
| 불변 조건·실패 동작 | 충분하지만 자기 말로 쓴 답은 아니다. 실패 시 기존 연결 유지, 허브가 Office로 먼저 접속하지 않음, 숨김은 표시만 바뀌고 DB는 그대로임을 확인했다. |
| 증거 범위 | 충분. 확인하지 않은 것(어두운 테마, 한국어 이름, 다른 사람의 실제 PC, 노트북 IP 변경)과 확인한 것(Fusion 실제 확인, 재배포 뒤 연결 유지, eevee-be 실제 화면, 자동 시험)을 확인했다. |
| B 결정(D21) | 일괄 진행 지시로 기본값을 정한 결정 1–6이 원한 것과 맞다고 확인했다(사후 확인). |

남는 한계: 답이 컨트롤러 설명을 확인하는 형태라 자기 말 답보다 근거가 약하다. 사용자는 이 평가를 본 뒤 2026-10-16 "피드백 확인 후 승인"이라고 답했다(D13 방식). 이 답이 G4다.
