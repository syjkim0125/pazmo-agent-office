# 2026-10-16 받은 팀 허브 요청을 Office Inbox에서 수락·거절 검증

Story: M14 · V16 · D22. 결정: [team-hub-office-inbox-decision.md](../understanding/team-hub-office-inbox-decision.md). 계획: [2026-10-16-1100-feat-team-hub-office-inbox-plan.md](../plans/2026-10-16-1100-feat-team-hub-office-inbox-plan.md).

## 구현 범위

- **허브:**
  - 연결 API 세 개: `incoming`, `incoming-accept`, `incoming-decline`. 프로토콜 2이고 팀원·레포 범위다.
  - 거절은 `state='cancelled'`로 두고 `closed_by`/`close_reason='declined'`/`close_note`를 남긴다. 새 칸은 자동 마이그레이션으로 더하고, 상태 CHECK는 바꾸지 않았다.
  - 요청자의 `outgoing`에 거절, 사유, 거절자를 넣었다.
  - 허브 웹에 담당자용 [거절]과 "거절됨" 표시를 더했다.
  - 같은 사람의 수락 재시도는 멱등이다.
  - 이미 닫힌 요청은 "이미 처리된 요청입니다."로 응답한다.
- **Office:**
  - 게이트웨이가 5초 동기화 때 받은 요청을 가져온다. 목록은 그것을 받아 온 토큰에 묶여 있어서, 연결을 바꾸면 이전 목록은 보이지 않는다.
  - 로컬 API: `GET /api/hub/incoming`과 수락·거절 POST(CSRF)를 더했다.
  - 다른 원점으로 연결을 바꾸면 성공한 뒤 이전 허브 작업을 취소한다. 취소 대상은 연결 직후에 정한다.
  - 동기화 한 번이 진행되는 중 연결이 바뀌면 그 회차의 제출·답변·취소를 멈춘다.
  - 초대 링크를 붙여넣으면 알아보고 안내한다.
- **화면:**
  - Inbox 열 맨 위에 "받은 팀 허브 요청" 카드를 둔다. 수락, 사유를 받는 화면 안 거절, 중복 클릭 방지, 처리한 카드 숨김이 있다.
  - 보낸 쪽 카드에 "거절됨 · 사유" 칩을 붙인다.
  - 연결을 바꿀 때와 해제할 때 확인 칸에 경고를 보인다.
- **덤으로 고친 것:** CLI `hub`(`runHub`)가 결과 줄을 출력한 **뒤에** 신호 처리기를 등록하던 순서를 바꿨다.
  - 이것이 root 시험의 간헐 실패 원인이었다: `tests/hub-cli.test.mjs` "the hub serves HTTPS on the given address…", 종료 코드 null.
  - 6회 반복에서 1회 재현해 테스트 이름을 확인했다. 같은 프로세스 안 시험으로 RED(출력 시점 처리기 0개)를 보인 뒤 고쳤다.

## 리뷰

- **Task 1–5:** 권한·취소가 걸린 Task는 가장 강한 모델이 리뷰했다. Task 5에서 Important 1건(밝은 테마 규칙이 없는 테두리 색)을 고쳤다. 나머지 Task는 승인됐고, 사소한 항목은 고치거나 원장에 남겼다.
- **브랜치 전체 리뷰(보안 포함): 고칠 것을 고치면 Ready.**
  - Important 1건: 교체 취소 대상을 연결 전에 정하던 경쟁. 연결 직후로 옮겼다.
  - 사소한 항목: 같은 사람 재수락 멱등, 수락 사전 검사 트랜잭션, 해제 경고, 묶음 제목.
  - 위 수정과 문서 항목을 한 번에 반영했고, 재검토 결과 Approved다.
- **남긴 것:**
  - 허브 접속 실패나 401일 때 받은 요청 목록이 잠시 이전 상태로 남는다. 누르면 연결 오류 안내가 나온다.
  - 목록 GET은 로컬 세션만 필요하다. 다른 허브 조회와 같다.
  - 허브 웹 거절에서 사유 길이(400)를 담당자 검사(403)보다 먼저 한다.
  - 받은 요청 응답에 본문 전체가 실린다(최대 50건).
  - 수락 사전 검사의 원자성은 추론으로만 보였다. node:sqlite가 동기라 결정적 시험이 어렵다.
