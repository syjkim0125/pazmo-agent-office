## Behavior and evidence boundary

The supported live service now runs `UnderstandingRunner` through the pinned controller and existing readonly ContainerPlanner transport. The worker gets the exact stored human answer, approved contract documents, frozen candidate identity, raw diff and joined results. It receives no operator token or approval tool. Its terminal report must identify the exact request, answer digest and evidence subject and assess all three understanding aspects. Nonempty text, extra approval fields, tool output, malformed JSON, wrong identity and nonzero process termination cannot approve. Context beyond the prompt bound fails before launch; evidence is not silently truncated.

The authenticated screen launch accepts only a request identity and answer digest. Browser-supplied assessments remain unsupported. An accepted model assessment calls the existing CompletionLedger evaluator, which applies the stored human decision without generating or replacing human text. The existing explicit delivery action remains separate. The prior README conversational approval is unchanged and was not converted into fabricated G4 answers.

A reviewer-purpose lease in the existing execution table owns every assessment's shared slot and task time. Its purpose is G4 assessment, not an additional kit Reviewer run. At most two explicitly requested attempts per request/answer are allowed; no automatic retries or new graph state owner. Unknown liveness holds the slot across restart. Current evidence can remain visible during its known readonly assessment, while evaluate/deliver still require every process closed. Closed malformed/failed assessments release their owned slot and preserve a failure code. Task cancellation, answer expiry or evidence invalidation rejects late results. A crash after closure but before assessment persistence cannot create approval; any remaining retry consumes the same bounded budget.
