## 질문과 답 (2026-10-28)

컨트롤러는 먼저 근거만 보였다: 승인된 범위(M15 문장, D25, V17 추가분), 파일별 diff 통계(엔진 0줄), 시험 943/943·타입 검사 0·Story 검사 0, 독립 리뷰 2회(Critical·Important 0), 확인하지 않은 것. 그다음 세 질문을 냈다. 사용자는 "답 초안 써줘, 확인 후 승인할게"라고 했다. 컨트롤러가 답 초안을 냈고, 사용자는 고치지 않고 이렇게 답했다.

> 피드백 확인 후 승인

사용자가 승인한 답(초안 그대로):

1. `./office --lean`에서 엔진이 멈춘 작업(멈춤 표시)의 상세에 [다시 실행]이 생긴다. 누르면 제목·내용·agent·위험도가 채워진 창이 열리고, 내용을 고쳐 확인하면 새 작업이 만들어진다. 그다음 멈춘 작업은 자동으로 취소되고, 두 작업 상세에 서로를 잇는 링크("이전 작업", "다시 실행한 작업")가 보인다. 이제 취소하고 다시 입력할 필요가 없다. 다만 새 작업은 기획부터 다시 하므로 G1 승인은 다시 한다. 멈추지 않은 작업과 `--lean`이 아닌 Claw Office는 그대로다.
2. 지금 멈춤인 작업만 다시 실행한다. 진행 중·결정 대기·완료·취소된 작업은 `NOT_STOPPED`로 거부하고 아무것도 저장하지 않는다. 멈춘 작업은 새 작업이 만들어진 뒤에만 취소한다. 입력 오류나 실행기 미준비로 새 작업을 못 만들면 아무것도 남지 않고 멈춘 작업은 그대로다. 한 작업은 한 번만 다시 실행된다. 두 번 눌러도 새 작업은 하나이고, 실행기 확인 중에 다른 탭에서 취소됐으면 새 작업을 만들지 않는다. 새 작업은 만들었는데 멈춘 작업 취소만 실패하면 새 작업은 남고, 화면이 "이전 작업 화면에서 취소하세요"라고 알린다. 그 작업에는 [다시 실행] 대신 취소만 남는다. 엔진·Claw Office·결정 규칙·한 번에 하나 대기열은 바뀌지 않고, 쓰기는 `127.0.0.1`·세션·CSRF를 거친다.
3. 확인한 것은 다음과 같다.
   - 자동 시험 943/943, 타입 검사 0.
   - 새 시험 13개: 기획 멈춤과 `UNKNOWN_RESULT` 멈춤의 다시 실행, 멈춤 아님 거부, 새 작업 거부 시 그대로, 동시 요청 한 번만, 실행기 확인 중 취소 시 거부, 취소 실패 시 응답과 기록, 기존 저장 파일의 표 추가, 서버의 세션·CSRF·409, 화면 문구와 창 채우기.
   - 가짜 실행기 lean Office를 브라우저로 확인했다.
   - 독립 리뷰 2회에서 Critical·Important는 0건이었다.

   못 한 것은 eevee-be 실제 Office에서의 다시 실행과 영어 화면의 실제 표시다. 엔진의 "프로세스 생존 불명" 실행 기록은 취소해도 남는다. 기존 취소와 같은 엔진 동작이다.
